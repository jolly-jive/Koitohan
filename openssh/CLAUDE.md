# CLAUDE.md(`openssh/`)

リポジトリの直下の `CLAUDE.md` の続きで、`openssh/` に関わる部分。全体の構成、コマンド、複数のディレクトリにまたがる注意は直下にある。

**OpenSSH(利用者作業用コンテナ)。** `openssh/build/`(Alpine + `openssh-server-pam`、`nss-pam-ldapd`、`shadow`、`gzip`、ソースからビルドした passwdqc)から `koitohan/openssh` をビルドする。ユーザーは LDAP のパスワードで SSH でログインし(ホストの `OPENSSH_PORT`)、`/logs/Hosts`(読み取り専用)、`/tftpboot/firmware` と `/tftpboot/configs`(ロール `admin` のみ)、`/tmp`(tmpfs)を使う。設計は `docs/basic-design.md` の 7 節、実装の要点は 7.9 節。

- ルートファイルシステムは読み取り専用(`read_only: true`)。起動時に書くものはすべて `/run/koitohan/`(tmpfs)に置き、`/etc/passwd`、`/etc/group`、`/etc/nslcd.conf`、`/etc/passwdqc.conf` はイメージの中でそこへのシンボリックリンクにしてある。イメージに元からあるアカウントは `/etc/passwd.base` と `/etc/group.base` に残してある。Dockerfile でリンクに置き換えたあとの `RUN` では、ユーザー名を引けない。
- `/etc/passwd` と `/etc/group` は `koitohan-update-users`(`openssh/build/update-users.sh`)が LDAP から作る。書き出すのは、`posixAccount` を持ち、`memberOf` がロールを指すユーザーだけ。複数のロールを指すユーザーは、いちばん弱いロールのグループにだけ入れる(`freeradius/CLAUDE.md` の「認証の流れ」を参照)。起動時に1回走るだけなので、LDAP を変更したら `docker compose exec openssh koitohan-update-users` で作り直す。GID は固定(`koitohan` 10000、`admin` 10001、`operator` 10002、`readonly` 10003)で、ファイルに数値で残るので変えないこと。
- 認証は sshd -> PAM(`pam_ldap`)-> `nslcd` -> LDAPS。`passwd` も同じ経路で、`pam_passwdqc` が先に判定する(`PASSWDQC_MIN`)。`nslcd` は降格後に証明書を読むので、`entrypoint.sh` が `/etc/koitohan/certs`(root しか入れない)から `/run/koitohan/nslcd-certs` へ写している。`/run/nslcd` は 0755 にしておく(0700 にすると、ユーザーの権限で動く `passwd` がソケットにつなげず、パスワードの変更だけが失敗する)。
- コンテナのホスト名は `OPENSSH_HOSTNAME`(コンテナ名とは別。証明書には関係しない)。プロンプト(`/etc/profile.d/koitohan.sh`。`ユーザー名@ホスト名:パス$`)と、`docker compose logs openssh` の各行に出る。複数台で動かすときに、どの台かを見分けるための名前。
- bind 用のパスワードは、マウントされた `/etc/koitohan/secrets/bindpw` を `entrypoint.sh` が読み、`/run/koitohan/bindpw` と `nslcd.conf` に書く。`ldapsearch` には `-y` でファイルから渡す。`-w` にすると、ログイン中のユーザーから `ps` で見える。
- sshd、`nslcd`、PAM は syslog にしか出力しないので、tftpd-hpa と同じく busybox の `syslogd` で標準出力へ流している(`docker compose logs openssh`)。
- `init: true` は外さないこと。ユーザーが残したプロセスを回収する。`entrypoint.sh` は `nslcd` か sshd が終了するとコンテナごと終了し、`restart: unless-stopped` に起動し直させる。
- sshd のホスト鍵は `make ssh_hostkeys` が Docker ホストで作り、`openssh/hostkeys/` を読み取り専用でマウントする。作り直すと全ユーザーの手元で警告が出るので、`make clean` の対象にしていない。
- メモリの上限(`mem_limit`)は、Docker ホストで cgroup のメモリコントローラが有効なときだけ効く。`/tmp` の tmpfs もこの上限に数えられるので、`/tmp` の容量は上限より十分に小さくしておく。

**接続元と外への通信(`OPENSSH_ALLOWED_NETWORKS`、`OPENSSH_EGRESS`)。** 機器が使うサービスの制限(`DEVICE_NETWORKS`)は、直下の `CLAUDE.md` の「接続元の制限」にある。OpenSSH は接続元が人の端末なので、別の変数 `OPENSSH_ALLOWED_NETWORKS`(書き方と既定は同じ)で、tftpd-hpa と同じ仕組み(`cap_add: NET_ADMIN`、`entrypoint.sh` の nftables、22/tcp)で絞る。sshd の設定(`Match Address`、`AllowUsers`)に替えないこと。接続を受けて認証まで進んでから断ることになり、範囲の外からの失敗が ppolicy のロックに数えられうる。`entrypoint.sh` はルールを入れたあと、`setpriv` で自分自身を `filtered` の引数付きで起動し直し、以降のすべてのプロセス(`syslogd`、`nslcd`、sshd)から `NET_ADMIN` を落とす。同じ表の出ていく側は `OPENSSH_EGRESS` で決める。値はユーザーが出られる範囲を表し、`none`(既定)、`any`、または `ssh` と `icmp` の並び(空白で区切る。順は問わない)。空、知らない語(以前の `ldaps` を含む)、`none` や `any` とほかの語の併用では起動しない。コンテナ自身が使うコンテナのネットワークのサブネット宛ての 636/tcp は、`any` 以外のどの値でも許す。サブネットは `OPENSSH_SUBNET` ではなく経路表から取る(テスト用のスタックでは Docker が割り当てるため)。`ssh` は宛先を問わない 22/tcp、`icmp` は echo request を足す(`traceroute` は raw ソケットが要るので、どの値でも使えない)。語を足すときは、`entrypoint.sh` の `case`、文書、スモークテストを揃え、syslog と TFTP を許す語は作らないこと。宛先の制限を入れるときは、別の変数にする(語の並びにアドレスを混ぜない。設計書の 7.8 節)。`any` は syslog と TFTP(514/tcp、514/udp、69/udp。宛先を問わない)だけを断る。`ssh` を含む値と `any` は、sshd のローカルの TCP フォワード(`ssh -J`)も許す。判定はフィルタを入れる段階で行い、起動し直したあとへ環境変数 `KOITOHAN_TCP_FORWARDING` で渡す。断るのは、Docker ホストが公開している syslog-ng と tftpd-hpa に届き、認証のないこれらを通じて、どのロールのユーザーも偽のログや `configs/` への書き込みができてしまうため(サービスからは Docker ホストが送信元に見え、`DEVICE_NETWORKS` では区別できない。設計書の 7.8 節)。断る番号は `compose.yaml` で公開しているホスト側の番号なので、公開ポートを変えたら揃えること。どの値でも、許さない通信は落とさずに断る(`reject`。TCP は RST)。`policy drop` だけに戻さないこと(ユーザーの手元でタイムアウトになる)。`entrypoint.sh` が `/run/koitohan/sshd_forwarding.conf` に `AllowTcpForwarding` を書き、`sshd_config` の冒頭で `Include` する(sshd は最初の値を使う)。フォワードを別の変数にしないこと。`none` と `icmp` ではパケットフィルタが sshd の接続にも掛かり、`ssh` と `any` では `nc` で同じことができるので、守りが増えない。宛先の制限、ロールごとの許可(`meta skgid`)、接続の記録は保留(7.8 節)。反映は `make up`(環境変数が変わるので OpenSSH が作り直される)。Docker ホストからの接続は `OPENSSH_SUBNET` のゲートウェイから届いたように見える。
