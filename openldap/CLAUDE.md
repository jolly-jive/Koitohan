# CLAUDE.md(`openldap/`)

リポジトリの直下の `CLAUDE.md` の続きで、`openldap/` に関わる部分。全体の構成、コマンド、複数のディレクトリにまたがる注意は直下にある。

**LDAP の初期投入。** `openldap/ldif/` は `/etc/koitohan/ldif` に読み取り専用でマウントされ、`openldap/build/entrypoint.sh` が**空のデータベースでの初回起動時にのみ**ファイル名順に適用する。その前に、`cn=config`(スキーマ `core`・`cosine`・`inetorgperson`・`nis`、`memberof` と `refint` のオーバーレイ、TLS)とサフィックスのエントリを `slapadd` で作る。LDIF は、`ldapi:///` だけで待ち受ける `slapd` を一時的に上げて `ldapadd` で入れる。最後まで済むと目印(`openldap/config/koitohan-seeded`)を置き、以降の起動では投入しない。LDIF が1つでも失敗したら、作りかけの設定とデータを消して終了する(LDIF を直せば次の起動でやり直せる)。目印がないのに `cn=config.ldif` か `data.mdb` があるとき(投入の途中で止められた)は、消さずに起動を断る。この2つの失敗を握りつぶさないこと。数字のプレフィックスがその順序を表す: `100-People`、`200-Roles`(`admin` / `operator` / `readonly` の `groupOfUniqueNames`)、`300-ServiceAccounts`(FreeRADIUS と OpenSSH のバインド用アカウント。名前は `FREERADIUS_SERVICE_ACCOUNT_NAME` と `OPENSSH_SERVICE_ACCOUNT_NAME`、パスワードは `secrets/` のファイル)、`400-PPolicy`(ppolicy のモジュール、オーバーレイ、`ou=Policies` のポリシー、サービスアカウントへの割り当て)、`900-ACL`(`{1}mdb` の `olcAccess` を置き換え。`ou=ServiceAccounts` にツリーの読み取り権限を付与。置き換えの変更なので、稼働中のデータベースにも `ldapmodify` で適用できる)。読み取り専用の bind はサービスアカウントが担う。LDIF や `.env` を変更して再投入するには、`openldap/data/` と `openldap/config/` の永続データを消す必要がある。ディレクトリの中身が失われるので、必ず事前に確認すること。データを消さずに足すときは、コンテナ内の `ldapi:///` から適用する(`docker compose exec -T openldap ldapadd -c -Q -Y EXTERNAL -H ldapi:/// < openldap/ldif/300-ServiceAccounts.ldif`。`-c` で、すでにあるエントリを飛ばす)。

**OpenLDAP のイメージ(`openldap/build/`)。** Alpine の `openldap` パッケージ(2.6)から `koitohan/openldap` をビルドする(以前は `osixia/openldap:1.5.0`。中身が OpenLDAP 2.4 と Debian 10 のまま更新が止まっていた)。場所は Alpine のパッケージのもので、設定は `/etc/openldap/slapd.d`(ホスト側 `openldap/config/`)、データは `/var/lib/openldap/openldap-data`(`openldap/data/`)、モジュールは `/usr/lib/openldap`、`ldapi:///` のソケットは `/var/lib/openldap/run/ldapi`(パッケージのビルドで決まっていて、クライアントの `ldapi:///` もここを見るので動かさないこと)。ルートファイルシステムは読み取り専用(`read_only: true`)で、`/run` と `/var/lib/openldap/run` が tmpfs。`slapd` は `-d 0` でフォアグラウンドに留め、syslog に出力させて busybox の `syslogd` で標準出力へ流す(`-d` に 0 以外を渡して標準エラーに出すと、時刻が 16 進数になり `TZ` も効かない)。イメージに bash はない。コンテナ内で実行するものは `sh` で書く(スモークテストの `LDAP_SUFFIX_SET` を参照)。オーバーレイを足すときは、`openldap-overlay-*` のパッケージを Dockerfile に足し、`olcModuleLoad` を書く。ppolicy のスキーマはモジュールに含まれている(2.4 のような別のスキーマの読み込みは要らない)。Alpine のリリースを上げるときは、OpenLDAP のマイナーバージョンが変わらないことを確かめる(2.6 から先へ上がると、`slapcat` での書き出しと入れ直しが要る場合がある)。`compose.yaml` の `ulimits: nofile: 1024` は外さないこと。`slapd` はファイル記述子の上限の数だけ表を確保する。Docker ホストによっては(Debian 13 の `docker.io` は `containerd.service` が `LimitNOFILE=infinity`)コンテナの上限が 1073741816 になり、`ch_calloc of 1 elems of 77309410752 bytes failed` を出して abort し、終了コード 139 で再起動を繰り返す(FreeRADIUS と OpenSSH も認証できなくなる)。値は同時の接続の上限を兼ね、1024 でも、使っているのは 13 ほど(接続するのは FreeRADIUS と OpenSSH だけ)。上げるとメモリが増える(計測では 1024 で 6.5 MiB、65536 で 53 MiB)。スモークテストが `slapd` の soft の上限を 1024 と決め打ちで見ている(`nofile`)ので、値を変えたらそちらも直す。設計は `docs/basic-design.md` の 3.1 節、4.5 節、4.6 節、8 節。

**パスワードポリシー(`400-PPolicy.ldif`)。** OpenLDAP の ppolicy が、最小の長さ(`PPOLICY_MIN_LENGTH`)と、認証の失敗によるロック(`PPOLICY_MAX_FAILURE`、`PPOLICY_FAILURE_WINDOW`、`PPOLICY_LOCKOUT_DURATION`。時間は秒)を強制する。文字の種類に応じた判定は passwdqc の側にある(`PASSWDQC_MIN`)。番号を `300` と `900` のあいだにしているのは順序に意味があるためで、動かさないこと。`pwdCheckQuality: 2` がハッシュ済みのパスワードを拒否するので、ハッシュを持つ LDIF(サービスアカウント)はオーバーレイより先に入れる。あとにすると、初回起動の投入が途中で止まる。同じ理由で、適用済みのデータベースにサービスアカウントを足すときは、パスワードを平文で渡す(`ldappasswd`)。既定のポリシーは `cn=default,ou=Policies`、サービスアカウントにはロックのない `cn=serviceaccounts` を `pwdPolicySubentry` で割り当てている(ロックされると全員の認証が止まる)。サービスアカウントを増やしたら、`generate_ldap_base.sh` の割り当てのループにも足すこと。ポリシーの値と割り当ては置き換えの変更として書いてあるので、`.env` を変えたあとや、ppolicy のない稼働中のデータベースには、`make ldap_dir` のあと `docker compose exec -T openldap ldapmodify -c -Q -Y EXTERNAL -H ldapi:/// < openldap/ldif/400-PPolicy.ldif` で適用できる(2回目以降は、追加の部分がエラーになって飛ばされる)。設計は `docs/basic-design.md` の 4.8 節。

**パスワードのハッシュ。** OpenLDAP は、パスワードを Argon2id(`{ARGON2}`)で保存する(以前は既定の `{SSHA}`。バックアップのアーカイブから漏れたときに割り出されやすい、という理由で改めた)。イメージに `openldap-passwd-argon2` を入れ、`openldap/build/entrypoint.sh` がモジュール `argon2` の読み込みと、フロントエンドのデータベースの `olcPasswordHash` を書く。初期投入のときに加えて、起動のたびにも書く(`olcPasswordHash` は `slapmodify -n 0` の置き換え。モジュールは、`slapcat -n 0` で見て、なければ足す)。以前のイメージで作ったディレクトリや、以前のバックアップから戻したディレクトリを、起動するだけで切り替えるため。モジュールを足すのは、必ず方式を書く前にすること。`slapmodify` は方式の名前を確かめずに書き、モジュールのない方式が書かれた `cn=config` は `slapd` も `slapcat` も読めなくなる(同じ理由で、切り替えたあとのディレクトリは以前のイメージでは起動しない)。パラメータはモジュールの既定(m=7168、t=5、p=1)のままにする。メモリは同時の bind の数だけ重なり、コンテナに上限がないので、増やさないこと(計測は `docs/basic-design.md` の 4.12 節)。すでにあるハッシュは書き換えず、次のパスワードの変更で替わる。サービスアカウントの初期投入のハッシュ(Docker ホストの `openssl`。`generate_ldap_base.sh`)と `olcRootPW` は `{SSHA}` のままにしている。どれも 48 桁のランダムな値で、ハッシュの強さに頼っておらず、Docker ホストに Argon2 のモジュールを求めないため。手順は `docs/configuration.md` の「パスワードのハッシュ」。

**LDAPS の接続元(`OPENLDAP_ALLOWED_NETWORKS`)。** 636/tcp は Docker ホストで公開しているが、ホストの外から受け付けるのは、この変数のアドレスだけ。値は `none`(既定。1台の構成で、外からは何も受け付けない)か、IPv4 のアドレスかプレフィックスの並び(2台の構成で相手の台。設計書の 12 節)。空、書式の誤り、`none` とアドレスの併用では起動しない。コンテナがつながっているネットワーク(デフォルトと `openssh`)のサブネットは、値によらず常に受け付ける(FreeRADIUS、OpenSSH、Docker ホスト自身はここから来る)。サブネットは `DOCKER_SUBNET` と `OPENSSH_SUBNET` ではなく経路表から取る(テスト用のスタックでは Docker が割り当てるため)。仕組みは OpenSSH と同じで、`cap_add: NET_ADMIN` を与え、`entrypoint.sh` が nftables のルールを入れたあと、`setpriv --bounding-set -net_admin` で自分自身を `filtered` の引数付きで起動し直し、以降のすべてのプロセス(`syslogd`、`slapd`、初期投入の `slapadd`)から落とす。これを外さないこと(`slapd` は root で起動するので、ルールを書き換えられる)。`ldapi:///` はソケットなのでフィルタに掛からない。1台の Docker ホストでは外のアドレスから送れないので(Docker の別のネットワークから公開ポートへ送っても、送信元は自分のネットワークのゲートウェイに見える)、スモークテストはルールの中身を、同じネットワーク名前空間に入れた別のコンテナの `nft list ruleset` で見る。外部の LDAP の管理ツールでつなぐ使い方は案内しない(ユーザーの管理は `bin/manage_users.sh`)。設計は `docs/basic-design.md` の 8 節の「接続元の制限」。
