# 冗長構成

[English](pair.md)

2台の Koitohan を対にして動かすと、片方の台が止まっても、機器のログインが続きます。機器は、両方の台を RADIUS、syslog、NTP のサーバーとして使います。2台の OpenLDAP は、LDAP ディレクトリを互いに複製し、どちらの台でも変更を受け付けます。

冗長構成は、いまのところ、1台の Docker ホストで2つの OpenLDAP のコンテナを動かして確かめただけです(スモークテスト)。1台では確かめられないもの(証明書に入れたアドレス、LDAPS の接続元の制限、台のあいだのネットワークが切れたとき)は、まだ2台の機械で試していません。

## 2台で共有するもの

| もの                                         | 2台のあいだ                                                        |
| -------------------------------------------- | ------------------------------------------------------------------ |
| ユーザー、ロール、パスワード、ロック         | OpenLDAP が複製します                                              |
| ログ                                         | 共有しません。機器が両方の台に送ります。                           |
| TFTP の `configs/`                           | 共有しません。どちらへ送るかは、機器ごとの設定で決まります。       |
| TFTP の `firmware/`                          | 共有しません。両方の台に置いてください。                           |
| `.env`、`clients.conf`、証明書               | 台ごとに持ちます。CA も台ごとに持ちます。                          |

## 設定

各台の `.env` に、次を設定します。

| 変数                        | 台A                            | 台B                            |
| --------------------------- | ------------------------------ | ------------------------------ |
| `OPENLDAP_HOST_ADDRESS`     | 台A のアドレス                 | 台B のアドレス                 |
| `OPENLDAP_PEER_ADDRESS`     | 台B のアドレス                 | 台A のアドレス                 |
| `OPENLDAP_ALLOWED_NETWORKS` | 台B のアドレス                 | 台A のアドレス                 |
| `OPENSSH_HOSTNAME`          | 台ごとの名前                   | 別の名前                       |

- アドレスは IPv4 で、2台が互いにつなぐときのアドレスです。`OPENLDAP_HOST_ADDRESS` は OpenLDAP の証明書に入り、相手の台がそれを確かめます。
- `LDAP_DOMAIN` は、2台で同じにしてください。
- 2台のあいだで 636/tcp が通るようにしてください。
- パスワードポリシーは LDAP ディレクトリの中にあるので、2台で共有されます。変えるときは、片方の台で変えてください(「[パスワードポリシー](configuration.ja.md#パスワードポリシー)」を参照)。

## 稼働中の Koitohan から対を作る

台A は、いま動いている Koitohan です。台B は新しい台です。

1. 台A の `.env` に上の設定を足し、`make` を実行します。証明書が、台A のアドレスを入れて、新しい CA から作り直されます。

2. 台B を、[クイックスタート](../README.ja.md#クイックスタート)のとおりに用意します。`.env` は台A のものを上の表のとおりに変えて使い、`clients.conf` は台A と同じものにします。`make` を実行し、まだ起動はしません。

3. 互いに相手の台の CA の証明書を渡します。台A の `CA/default-ca.pem` を台B の `openldap/peer/ca.pem` に、台B のものを台A の `openldap/peer/ca.pem` に置きます。証明書は秘密ではありませんが、届いたものが送ったものと同じかを確かめてください。たとえば、両方の端で次の出力を比べます。

   ```sh
   openssl x509 -noout -fingerprint -sha256 -in openldap/peer/ca.pem
   ```

4. 台A で、スタックを起動し直します。新しい証明書と相手の台を読み込みます。

   ```sh
   make down && make up
   ```

5. 台B で、スタックを起動します。台B の OpenLDAP は空で、台A から LDAP ディレクトリをすべて受け取ってから使えるようになります。それまでは、台B の FreeRADIUS は応答せず、台B には SSH でログインできません。終わったことはログでわかります。

   ```sh
   make up
   docker compose logs -f openldap    # "received the data from the other host" が出るまで
   ```

6. 両方の台で確かめます。`bin/check_services.sh` が `OK pair: the same ... entries as the other host` を出します。

7. 機器に、台B を2つ目の RADIUS、syslog、NTP のサーバーとして足します。

新しい2台から対を作るときは、まず台A だけを相手なし(`OPENLDAP_PEER_ADDRESS='none'`)で起動して、LDAP ディレクトリを初期投入させてから、上の手順に進んでください。空の2台が互いを相手にして起動すると、どちらも相手を待ち続けます。

## 対で動かすときの決まり

- **両方の台で同時にユーザーを管理しないでください。** どちらの台で管理してもかまいませんが、一度に片方だけにします。同時に変えると、2人のユーザーが同じ番号を持ったり、ロールの2つの変更のうち片方が消えたりします。
- **総当たりを受けているときは、両方の台の FreeRADIUS を止めてから、パスワードを変えてください。** 認証の失敗は両方の台で記録され、片方の台で変えた瞬間に、もう片方の台で失敗が重なると、古いパスワードに戻ることがあります。片方の台だけを止めると、機器はもう片方の台へ切り替えます。そのあいだは、機器のローカルのアカウントでログインしてください。

  ```sh
  docker compose stop freeradius     # 両方の台で
  bin/manage_users.sh passwd <ユーザー>  # 片方の台で
  docker compose start freeradius    # 両方の台で
  ```

- **片方の台で `make certs`(または CA を作り直した `make`)を実行したら、** 新しい `CA/default-ca.pem` をもう片方の台の `openldap/peer/ca.pem` に置き、そちらで `docker compose restart openldap` を実行してください。それまでは、2台は複製しません。
- 両方の台の時計を同期させておいてください(`make host_check`)。複製は変更の時刻で順序を決めます。
- `clients.conf` と `firmware/` は、両方の台で変えてください。

## 片方の台が壊れたとき

壊れた台の OpenLDAP の永続データを消して、起動します。手順 5 の台B と同じく、もう片方の台からすべて受け取ります。

```sh
make down
sudo find openldap/data openldap/config -mindepth 1 ! -name .gitkeep -delete
make up
```

台を一から組み直すときは、「[新しいホストに復元する](backup.ja.md#新しいホストに復元する)」のとおりに進めますが、`bin/restore_ldap.sh` は使いません。LDAP ディレクトリは、もう片方の台から届きます。新しい台は新しい CA を持つので、手順 3 のとおりにもう片方の台へ渡し、そちらの OpenLDAP を起動し直してください。

## 2台が食い違ったとき

`bin/check_services.sh` は、2台の LDAP ディレクトリをエントリごとに比べ、`WARN` を出します。

- `pair: differs from the other host`: 2台が違うエントリを持ち、数秒待っても変わりません。下の行に、そのうちのいくつかが出ます(`only here` と `only there`。最後に変わった時刻つき)。
  - まず、複製が両方向に通っているかを見てください。もう片方の台でも `bin/check_services.sh` を実行し、そちらが `cannot read the other host` を出すなら、変更がそちらへ届いていません。それを直せば、2台は追いつきます。
  - 両方の台が互いを読めているのに残る食い違いは、ひとりでには直りません。片方の台をバックアップから戻したときに、もう片方の台がデータを残していた場合に起こりえます(「[冗長構成の復元](backup.ja.md#冗長構成の復元)」を参照)。どちらの台の LDAP ディレクトリが正しいかを決め、もう片方の台の永続データを消して起動してください(「[片方の台が壊れたとき](#片方の台が壊れたとき)」と同じ手順)。
- `pair: cannot read the other host`: もう片方の台が止まっている、台のあいだのネットワークが切れている、または相手の台がこちらを受け付けていません(相手の台の `OPENLDAP_ALLOWED_NETWORKS`、または `make certs` のあとに CA の証明書を渡し直していない)。

## 1台に戻す

残す台で `OPENLDAP_PEER_ADDRESS='none'` と `OPENLDAP_ALLOWED_NETWORKS='none'` にして、`make down && make up` を実行します。機器から、もう片方の台を外してください。

## バックアップからの復元

戻すのは片方の台だけにし、もう片方の台には受け取らせます。「[冗長構成の復元](backup.ja.md#冗長構成の復元)」を参照してください。
