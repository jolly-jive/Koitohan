# ユーザーズガイド

[English](user-guide.md)

Koitohan につながったネットワーク機器にログインして作業する人のためのガイドです。Koitohan を動かしているサーバーの構築と運用は、こいとはん管理者が行います。その手順は [README](../README.ja.md) と運用ガイドにあります。

> こいとはん管理者へ: このガイドの `<ホスト>` とポート番号 `2222` は、自分の環境の値に書き換えてから配ってください。

## Koitohan でできること

- **1つのアカウントで、すべての機器にログインできます。** ユーザー名とパスワードは Koitohan が一か所で管理し、機器ごとに登録する必要はありません。機器でできることは、ロールで決まります。
- **機器のログを読めます。** 機器が送った syslog は、Koitohan に機器ごとに保存されます。
- **ファームウェアを配り、コンフィグのバックアップを取り出せます**(ロール `admin` のみ)。機器は Koitohan と TFTP でファイルをやり取りします。
- **自分でパスワードを変えられます。**

ログとファイルを扱うために、ユーザー専用の作業用の環境があります。Koitohan のサーバーそのものには、こいとはん管理者しか入れません。作業用の環境は SSH でログインする小さな Linux で、ロールに応じたログとファイルだけが見えるようにしてあります。

## ロール

ユーザーには、`admin`、`operator`、`readonly` のどれか1つのロールがあります。ロールを変えたいときは、こいとはん管理者に頼んでください。

| ロール     | 機器での権限                     | 作業用の環境でできること                         |
| ---------- | -------------------------------- | ------------------------------------------------ |
| `admin`    | 管理者(設定の変更を含む)         | ログを読む、ファームウェアを置く、コンフィグを取り出す |
| `operator` | 運用者(範囲は機器による)         | ログを読む                                       |
| `readonly` | 参照のみ                         | ログを読む                                       |

機器での具体的な権限は、機器の種類と設定によって違います。分からないときは、こいとはん管理者に確かめてください。

## 作業用の環境にログインする

機器へのログインと同じユーザー名とパスワードで、SSH でログインします。公開鍵認証には、まだ対応していません。

```sh
ssh -p 2222 alice@<ホスト>
```

- ホームディレクトリはありません。`scp` と `sftp` では、作業用の環境の側のパスを絶対パスで指定します。
- 書き込めるのは、下の表で「読み書き」とした場所だけです。
- 作業用の環境から機器などのほかのホストへ接続できるかどうかは、こいとはん管理者の設定によります。接続できる場合は、ローカルのポートフォワーディング(`ssh -J`、`ssh -L`)も使えます。そのほかのフォワーディングは使えません。

| パス                  | 内容                             | admin    | operator | readonly |
| --------------------- | -------------------------------- | -------- | -------- | -------- |
| `/logs/Hosts/`        | 各機器の syslog                  | 読み取り | 読み取り | 読み取り |
| `/tftpboot/firmware/` | 機器へ配布するファイル           | 読み書き | なし     | なし     |
| `/tftpboot/configs/`  | 機器がアップロードしたコンフィグ | 読み書き | なし     | なし     |
| `/tmp/`               | 作業用の置き場所(32MB)           | 読み書き | 読み書き | 読み書き |

`/tmp/` の中身は、作業用の環境が作り直されると消えます。残したいものは手元に取り出してください。

## ログを読む

機器のログは、`/logs/Hosts/<機器>/<機器>.log` にあります。`<機器>` は、機器が syslog に載せたホスト名です(載せない機器ではアドレスになります)。

- ファイルは1日ごとに切り替わり、前日以前のものは日付の付いた名前になります(`<機器>.log-2026-10-10`)。
- 2日以上前のものは圧縮されています(`<機器>.log-2026-10-10.gz`)。`zgrep`、`zcat` で読めます。

```sh
# 全機器の今日のログから、特定のメッセージだけを取り出す
ssh -p 2222 alice@<ホスト> 'grep -h LINK-3 /logs/Hosts/*/*.log' > link.txt

# 同じことを、2026-10-10 のログで行う
ssh -p 2222 alice@<ホスト> 'zgrep -h LINK-3 /logs/Hosts/*/*.log-2026-10-10.gz' > link.txt

# 1台の機器の、ある日のログを手元に取り出す
scp -P 2222 'alice@<ホスト>:/logs/Hosts/core-switch/core-switch.log-2026-10-10.gz' .
```

## ファームウェアを配る、コンフィグを取り出す(admin のみ)

`/tftpboot/firmware/` に置いたファイルを、機器が TFTP で取得します。機器がアップロードしたコンフィグは `/tftpboot/configs/` に入ります。

```sh
# ファームウェアを置く
scp -P 2222 image.bin alice@<ホスト>:/tftpboot/firmware/

# コンフィグのバックアップを手元に取り出す
scp -P 2222 alice@<ホスト>:/tftpboot/configs/core-switch.cfg .
```

機器からは、`firmware/<ファイル名>`、`configs/<ファイル名>` というパスで指定します。Cisco IOS での例:

```
copy running-config tftp://<ホスト>/configs/core-switch.cfg
copy tftp://<ホスト>/firmware/image.bin flash:
```

- 置いたファイルを機器が取得するには、「その他」の読み取り権限が要ります。0600 で置いたファイルは、`chmod 644` で直してください。
- `configs/` のコンフィグは、読む、複製する、削除することができます。その場での書き換えはできません。
- 転送はバイナリモードで行ってください。

## パスワードを変える

作業用の環境にログインして、`passwd` を実行します。変えたパスワードは、機器へのログインにも使われます。

新しいパスワードには、含む文字の種類(大文字、小文字、数字、その他)に応じた最小の長さがあります。既定の値は次のとおりです(こいとはん管理者が変えている場合があります)。

| 含む文字の種類 | 最小の長さ |
| -------------- | ---------- |
| 3種類以上      | 8          |
| 2種類          | 10         |
| 1種類          | 12         |

先頭の大文字と末尾の数字は、種類に数えません。たとえば `Password1` は1種類として扱われます。

## ログインできないとき

**認証に続けて失敗すると、しばらくロックされます。** 失敗の回数は、機器へのログインと作業用の環境へのログインで共通に数えます。成功すると 0 に戻ります。

- ロックされているあいだは、正しいパスワードでも拒否されます。パスワードを誤ったときと見分けがつきません。
- ロックは時間が経つと解けます。急ぐときは、こいとはん管理者に解除を頼んでください。

**パスワードを忘れたときは、** こいとはん管理者に再発行を頼みます。受け取ったパスワードでログインしたら、`passwd` で自分のパスワードに変えてください。

**作業用の環境に接続できないときは、** 次のことが考えられます。

- 同じ接続元から認証の失敗が続くと、作業用の環境は、その接続元からの接続をしばらく受け付けません。時間をおいてから試してください。
- 作業用の環境は、こいとはん管理者が決めたネットワークからの接続だけを受け付けます。応答がなくタイムアウトするときは、接続元がその範囲に入っているか、こいとはん管理者に確かめてください。
