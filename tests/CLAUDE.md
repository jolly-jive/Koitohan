# CLAUDE.md(`tests/`)

リポジトリの直下の `CLAUDE.md` の続きで、`tests/` に関わる部分。全体の構成、コマンド、複数のディレクトリにまたがる注意は直下にある。

**スモークテスト(`tests/`)。** `make test` は `compose.yaml` に `tests/compose.test.yaml` を重ね、すべてのコンテナをプロジェクト `koitohan-test` として起動する(イメージをビルドし直すので、`koitohan/openldap`、`koitohan/freeradius`、`koitohan/tftpd-hpa`、`koitohan/openssh`、`koitohan/chrony` のタグは作業ツリーの内容になる。稼働中のコンテナは作り直すまで古いイメージのまま)。差し替えるのはポート(公開しない)、永続データ(匿名ボリューム)、`clients.conf`、証明書を含む生成物(`tests/generated/`。テストが `scripts/` の生成スクリプトで毎回作り、終わると消す。証明書は `tests/generated/CA/` に作り、OpenLDAP、FreeRADIUS、OpenSSH の証明書のマウントを差し替える。本番の `CA/` は読まない。`tests/generated/CA/` は、`make private_dirs` と同じく 0700 にする。FreeRADIUS の鍵は 0644 なので、ディレクトリを緩めないこと)、ログの書き込み先(syslog-ng は `tests/generated/syslog-ng/log`。OpenSSH の `/logs/Hosts` にもそこの `Hosts/` を `:ro` でつなぎ、本番と同じ経路にする)、OpenSSH に見せる TFTP のディレクトリ(匿名ボリューム)、tftpd-hpa の TFTP のディレクトリ(`firmware/` は `tests/generated/tftpboot/firmware` を `:ro` で。取得するファイルは起動の前に置く。`configs/` は匿名ボリュームで、起動のあとに `docs/tftp.md` の手順と同じ所有者と権限にする)、アップロードの上限(`TFTP_UPLOAD_MAX_BYTES` を 64KiB にして export する)、sshd の `PerSourcePenalties`(`tests/sshd_test.conf` で無効にする)、OpenSSH がユーザーを読み直す周期(`KOITOHAN_UPDATE_USERS_INTERVAL` を 5 秒にする)だけで、イメージとその他のマウントは本番と同じ。テストアカウントは初期投入に含めず、起動のあとでテストが作る。`admin01` / `operator01` / `readonly01` は `bin/manage_users.sh` で登録し(パスワードは `tests/smoke.sh` の `PASS_*`。passwdqc を通る必要がある)、ロールのない `norole01` はスクリプトでは作れないので、OpenLDAP のコンテナの `ldapi:///` から直接作る。`norole01` を先に作るのは、番号の割り当てが、すでにあるユーザーの次から始まることを確かめるため。ロール以外のグループだけを持つ `other01`(`cn=guest,ou=Roles`。未定義のロール)と `other02`(`cn=staff,<サフィックス>`。`ou=Roles` の外)、`operator` と `guest` の両方を持つ `other03` も、3つのテストアカウントのあとで `ldapi:///` から作る(番号は 20001〜20003。スクリプトの番号を動かさないため)。要求は FreeRADIUS のコンテナ内から `radclient` で送り、`Net.Src.IP` で送信元を `127.0.0.N` に変えて `tests/clients.conf` のクライアント(= `nas_type`)を選ぶ。応答の照合のあと、`127.0.0.1` の detail ログ(`auth-detail`、`reply-detail`)を別の名前に移してもう一度認証し、FreeRADIUS が作り直すことを確かめる(ログローテーションが頼る動作。イメージを更新したときの退行の検出)。続いて、Docker ホストから OpenLDAP のコンテナのアドレスへ `openssl s_client` で(テストの CA の、FreeRADIUS のクライアント証明書を使う)、TLS 1.3 は成立し、TLS 1.2 は断られることを確かめる。続けて OpenLDAP の接続元の制限を `check_ldap_networks`(値、値が足す送信元)で確かめる(`ldap networks`)。1台の Docker ホストでは外のアドレスから送れないので、ルールの受け付ける送信元を、同じネットワーク名前空間に入れた別のコンテナ(`--network container:`、`NET_ADMIN` 付き)の `nft list ruleset` で読み、コンテナのネットワークのサブネットと値の和に一致することを見る。稼働中の OpenLDAP(テストは `OPENLDAP_ALLOWED_NETWORKS='none'` を export する)と、値を与えた使い捨てのコンテナ(`docker run` でデフォルトのネットワークに置く。`compose run` にしないこと。エイリアス `openldap` が付き、FreeRADIUS と OpenSSH の接続が向かいうる。秘密のファイルがないので起動スクリプトは止まるが、`sleep` で名前空間を残す)の2つを見る。続けて、稼働中の OpenLDAP の中で `nft` が断られること(`NET_ADMIN` を落としたこと)を見る。最後に OpenLDAP のコンテナを再起動し、`ldapi:///` 経由の `ldapwhoami` でバインドできることを確かめる(同じコンテナの2回目の起動で、初期投入をやり直そうとしたり、起動スクリプトが止まったりしないことの確認)。この確認は FreeRADIUS を通さない(RADIUS の側は、あとの `ldap restart` と `ldap down` の確認で見る)。続いて接続元の制限を確かめる。Docker ホストからテスト用のスタックの syslog-ng(1514 の udp と tcp。フィルタは syslog-ng の中にあるので、範囲の外でも tcp の接続は成立し、メッセージだけが捨てられる)と tftpd-hpa(`curl` の `tftp://`)に送り、FreeRADIUS には同じイメージの別のコンテナ(`compose run --entrypoint radclient`。Docker ホストには `radclient` がない)からコンテナのアドレスへ送り(`tests/clients.conf` の末尾の3つが、プライベートアドレスのクライアント)、届くことを見てから(syslog は続けて `check_syslog_sender` で、メッセージが名乗ったホスト名 `smoke-allowed` のディレクトリができていないこと、行頭が受信した時刻であること、名乗った名前が行に残っていることを見る)、`DEVICE_NETWORKS` を `192.0.2.0/24` にして生成し直し、3つのコンテナを作り直して、届かないことを見る。そのあいだ(作り直す前)に、転送の記録がコンテナの中の `tftpd.log` に入っていることと、ファイルを別の名前に移してもう一度取得すると `syslogd` が作り直すことを確かめる(移してから2秒待つ。`syslogd` が開き直すのは1秒ごと)。続けて、Docker ホストから `configs/` へアップロードし(新しいファイル、同じ名前への短いファイルでの上書き、上限ちょうど、上限を1バイト超えたもの)、残ったものの所有者、権限、大きさ、中身を見る。`firmware/` へのアップロードは、tftpd-hpa がエラーを返し、ファイルができないことを見る。テスト用のスタックは自前の `firmware/` をマウントするので、`compose.yaml` の `firmware/` が読み取り専用であることは、`docker compose -f compose.yaml config` の出力で別に見る。届かないことを見たあとで、誤った値(空、`example.com`、`10.0.0.0/33`)で FreeRADIUS、tftpd-hpa、OpenSSH、OpenLDAP(加えて `none 10.0.0.0/8`)を `compose run` で使い捨てに起動し、理由を出して止まることを見る(終了ステータスだけでなくメッセージも見る。ほかの理由での失敗を合格にしないため。起動してしまったものは `timeout` で止めて消す)。`scripts/generate_device_networks.sh` も、`example.com`、`10.0.0.0/33`、`999.0.0.0/8` で失敗し、`device_networks.conf` を書き換えないことを見る(syslog-ng 自身はこれらを黙って受け付ける)。chrony は、テストが `COMPOSE_PROFILES=ntp` を export して起動する(`.env` に左右されない。`bin/` のスクリプトにも渡る)。確認の関数は `check_ntp`(確認の名前、対象、期待)で、同じイメージの別のコンテナでクライアントの chronyd を動かし、`chronyc ntpdata` の Leap、stratum、受信の数から `served`、`unsynchronised`、`no reply` を判定する。問い合わせの前に、`entrypoint.sh` のログの行(`serving the host clock`、`stopped serving`)を待つ(配り始める前は「同期していない」と答えるため)。範囲の中と外は、ほかのサービスと並べて見て、`DEVICE_NETWORKS` を変える作り直しに chrony も含める。誤った値は、ほかのサービスのループとは別に(書式の誤りは chrony 自身のメッセージになる)、空、`example.com`、`10.0.0.0/33`、`999.0.0.0/8`、`NTP_MAX_ERROR_US=abc` で見る。そのあと `NTP_MAX_ERROR_US=0` で作り直して `unsynchronised` を見る。これより後ろに chrony を使う確認はない。テストは `DEVICE_NETWORKS` を自分で決めて export する(`.env` の値に左右されない。Docker がテスト用のネットワークにプライベートアドレスを割り当てることを前提にしている)。syslog-ng の `/var/log` は、起動の前に Docker ホストで `Hosts/` まで作った `tests/generated/syslog-ng/log` にしている(匿名ボリュームだと root 所有になり、uid 1000 の syslog-ng が書けない。Docker ホストのユーザーが uid 1000 であることは、本番の `make up` が `syslog-ng/log/Hosts/` を作るときと同じ前提)。syslog-ng の起動は制御ソケット(`syslog-ng-ctl stats`)で待つ。捨てたメッセージは何も残らないので、起動の前に送ると「届かない」確認が偽って通る。SSH の確認は RADIUS のあとに行う。ポートを公開しないので、Docker ホストからコンテナのアドレスへ直接 `ssh` し、パスワードは `SSH_ASKPASS` で渡す。ロールごとのログイン、`/tftpboot` の権限、外への通信(`OPENSSH_EGRESS=none`。`docker run` で `openssh` のネットワークに置いた `nc` の待ち受け(22、8080、514 の tcp)に、TCP、ICMP、`ssh -W` で届かないこと。確認の関数は `check_egress_tcp`、`check_egress_icmp`、`check_egress_forwarding` で、ポートと期待(`reached`、`refused`、フォワードは `prohibited` も)を1つずつ受け取り、結果の対象の列に値を出す。TCP は `wget` の `Connection refused` で、すぐに断られることを見る。黙って落とす形だと、タイムアウトで合格してしまうため。ICMP は `Operation not permitted` を見るが、コンテナから出ていくパケットは落としても断っても EPERM になるので、パケットフィルタが止めたことしかわからない。`compose run` にしないこと。`compose ps -q openssh` に混ざる。フォワードは `LogLevel=INFO` で `administratively prohibited` を見て、パケットフィルタに落とされた場合と見分ける)、圧縮されたログの `zgrep`(logrotate の代わりに、テストが Docker ホストで `tests/generated/syslog-ng/log/Hosts/smoke/` に置いたもの)、syslog-ng が書いたログ(接続元の制限の確認で届いた `koitohan-smoke [allowed]` の行。Docker ホストから送ったものはすべて、ネットワークのゲートウェイのアドレスの1つのファイルに入るので、確認ごとの名前を本文に入れて見分ける。`syslog_log_of_host` がそのパスを返す)を読めること(`syslog-ng.conf` の `dir-perm` と `perm`)、`passwd` による変更と拒否、OpenLDAP の再起動のあとのログインを確かめる。`passwd` の確認は `readonly01` のパスワードを変えるので、そのあとに `readonly01` を使う確認を足すときは新しいパスワードを使う。その直後に、`ou=People` の `userPassword` がすべて `{ARGON2}` であることを見る(`hash scheme`。この時点で `bin/manage_users.sh`、`ldapi:///` からの `ldappasswd`、`passwd` の3つの経路が揃う。値は base64 で返るので、`{ARGON2}$` にあたる `e0FSR09OMn0k` で見て、数が少なすぎるときも合格にしない)。そのあと `bin/manage_users.sh` の確認が続く(テストアカウントが 10000〜10003 を持つので、番号は 10004 から始まる)。`smoke01`(`operator`)を登録した直後に、`ldapi:///` から `admin`、続いて `readonly` を足し、いちばん弱いロールが RADIUS と SSH の両方で効くことを見る(足す順序に意味がある。`readonly` が `memberOf` の最後に来るので、最初の値だけを見ても、いちばん強いロールを採っても合わない)。続けて、`smoke01` の SSH のセッションを開いたまま、`ldapi:///` から `readonly` だけを外し、`koitohan-update-users` を呼ばずに、セッションが 30 秒以内に切れることと、`operator` で入れることを見る(`periodic`。テスト用のスタックは `tests/compose.test.yaml` で、OpenSSH が読み直す周期を 5 秒にしている)。1つのロールに戻すのは、直後の `role` の確認に任せている(ここでもセッションを開いておき、切れることを見る)。その途中で ppolicy を確かめる。最小の長さとハッシュ済みの値の拒否は、OpenLDAP のコンテナの `ldapi:///` から `operator01` 本人として書き込んで確かめる。長さはポリシーの `pwdMinLength` から決め、1文字短いものが拒否され、ちょうどの長さが通ることを見る(通したあと `PASS_OPERATOR` に戻す)。ロックは、`pwdMaxFailure` より1回少なく失敗させた `smoke01` がまだ通ることを見てから(成功で数え直しになる)、`pwdMaxFailure` の回数だけ RADIUS で失敗させた `smoke01` が RADIUS と SSH の両方で拒否され、`unlock` で戻ることで確かめる。`unlock` を外さないこと(直後の `delete` の確認が、ロックだけで合格するようになる)。`delete` のあとに、検索の件数に上限がないことを見る(`size limit`。`ou=SizeLimit` に以前の上限を超える 520 件を `ldapi:///` から入れ、OpenSSH のコンテナから証明書で LDAPS の `ldapsearch` をして、終了ステータス 0 で全件が返ること。見終わったら `ldapdelete -r` で消す。あとのバックアップや復元の確認に混ぜないため)。続いて memberof と refint を見る(`memberof`。スクリプトを通さず `ldapi:///` から、`cn=readonly` に先に `uniqueMember` を足してから `addcheck01` を作り、`memberOf` が付くこと(AddCheck)と、`ldapdelete` したあとにグループから外れること(refint。別のスレッドで動くので、6 秒まで読み直す)。`addcheck01` は `posixAccount` を持たないので、OpenSSH と FreeRADIUS の確認に影響しない)。テストアカウントに失敗を重ねる確認を足すときは、その回数がロックに届かないようにすること(成功すると 0 に戻る)。続いて、OpenSSH を `recreate_egress` で `ssh`、`icmp`、`icmp ssh`(順を入れ替えて、並びの読み取りを見る)の順に作り直し、それぞれ許すものだけが届くことを見る(`ssh` では、`ssh -W` の 22 番以外を、sshd ではなくパケットフィルタが断る)。続いて `any` で作り直して外へ届くことと、514/tcp、514/udp、69/udp は断られることを見て(待ち受けは 514/tcp でも応答するので、`Connection refused` はパケットフィルタからとわかる。UDP は `nc` の終了ステータスが 1(EPERM)になり、ほかの番号では 0 になることを見る。`ssh -W` で 514 を指定すると `connect failed: Connection refused` になる)、続いて `OPENSSH_ALLOWED_NETWORKS=192.0.2.0/24` で作り直し、sshd が待ち受けていること(コンテナの中からループバックで見る)と、Docker ホストからの接続がタイムアウトすることを確かめる。`OPENSSH_EGRESS` は2回目の作り直しで、範囲は直後の作り直しで元に戻る(この3つの順序を入れ替えないこと)。OpenSSH のアドレスが変わる(`wait_ssh_ready` が取り直す)。作り直したコンテナに入れることを見る。続いて、FreeRADIUS と OpenSSH が証明書で bind したことを、OpenLDAP のログで見る(`service identity`。`BIND dn="cn=freeradius,cn=koitohan" mech=EXTERNAL` と `cn=openssh` の行があること、ユーザーのほかの simple bind がないこと。ここまでのログインはすべてこの bind を通り、OpenLDAP のコンテナはまだ作り直していないので、ログが揃っている)。続いて、本番の `CA/` が書き換えられていないことと、OpenLDAP の管理者にパスワードがないことを見る(`admin pass`。`cn=config` に `olcRootPW` が 0 個、`cn=admin` の2つに simple bind すると `Invalid credentials`)。そのあと `ldapi:///` から2つに `olcRootPW` を書き、そのパスワードで bind できることを見ておく(再起動で消えることの対照)。続く OpenLDAP の再起動で、FreeRADIUS の2本の接続は切れる。ここから `ldap restart` の確認まで、RADIUS を通す確認を足さないこと(その確認が、切れた接続に最初にぶつかる要求であることに頼っている)。OpenLDAP の再起動の前に `ldapi:///` から TLS の下限を 1.2 に、パスワードのハッシュの方式を `{SSHA}` に下げ、サービスの対応づけ(`olcAuthzRegexp`)とアクセス制御の `{2}` を消し、検索の件数の上限を 500 に、memberof の AddCheck を無効、RefInt を有効にしておき(この順で。memberof は RefInt が有効なあいだ AddCheck を断る)、再起動のあとに 1.3 と `{ARGON2}` と対応づけと `unlimited` と memberof の設定へ戻っていること(アクセス制御が戻ったことは、そのあとの SSH と RADIUS のログインが示す)、書いた `olcRootPW` が消え、そのパスワードで bind できなくなったことを見る。続けて、RADIUS の最初のログインが通ることを見る(`ldap restart`。`backlog_on_failed_conn` がないと拒否される)。そのあと OpenLDAP を `stop` し、RADIUS に応答がないこと(`ldap down`。`radclient` の `No reply from server` を見る。拒否が返れば不合格)と、`start` のあとの最初のログインが通ることを見る。`bin/check_services.sh` は `check_services`(対象、期待)で確かめる。期待は `healthy`(終了ステータスが 0 で NG がない)か NG の行の頭で、そのときは NG がその1行だけで終了ステータスが 1 であることを見る(WARN は Docker ホストのディスクの空きに左右されるので数えない)。健全なときと、`configs/` を root 所有にしたとき、syslog-ng を `stop` したとき(`DEVICE_NETWORKS` を変える作り直しの直前)、chrony が配るのをやめたとき(`NTP_MAX_ERROR_US=0` のあと)を見る。最後にバックアップと復元を確かめる。`bin/backup.sh -k 2` で `tests/generated/backup/` に書き出し(古い名前のファイルを2つ置いておき、1つ消えることを見る)、中身がテスト用のスタックのファイルであることを見てから、`smoke02` を消し、`configs/` のファイルを消す。OpenLDAP のコンテナを `rm -s -f -v` で匿名ボリュームごと消して `bin/restore_ldap.sh` で戻し(その前に、中身があると断ることを見る)、OpenLDAP を起動して FreeRADIUS を作り直す。初期投入が走っていないこと、`smoke02` が RADIUS で通ること、変えたあとのパスワードで `readonly01` が SSH に入れること、次の番号が 10006 であること、`configs/` のファイルが所有者ごと戻ることを見る。OpenLDAP を作り直すので、これより後ろに確認を足すときは、そのことを前提にすること。確認の結果は `report`(名前、対象、合格の文言、`WHY`、FAIL のときに添える出力)で数えて出す。`WHY` が空なら合格。FAIL のときは 1 を返すので、サービスのログを添えるときは `report ... || show_logs <サービス>` と書く。確認を足すときも、`COUNT` や `printf` を直に書かないこと。
