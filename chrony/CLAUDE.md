# CLAUDE.md(`chrony/`)

リポジトリの直下の `CLAUDE.md` の続きで、`chrony/` に関わる部分。全体の構成、コマンド、複数のディレクトリにまたがる注意は直下にある。

**chrony(時刻の配布)。** `chrony/build/`(Alpine + `chrony`)から `koitohan/chrony` をビルドする。任意のサービスで、`compose.yaml` の profile `ntp` に入れ、`.env` に `COMPOSE_PROFILES='ntp'` があるときだけ起動する(既定は無効。やめたときの反映は `make down && make up`。`make up` だけでは動いているコンテナが残る)。上流を持たず、コンテナと共有しているホストの時計を `-x`(時計に触れない)で配る。ホストの同期は前提で、`make host_check` が `timedatectl` で確かめる。`entrypoint.sh` は `DEVICE_NETWORKS` から `/run/koitohan/chrony.conf` に `allow` を書く。数字、`.`、`/` 以外を断るのは、chrony が `allow` のホスト名を引いて受け入れてしまうため(この確認を外さないこと)。書式の誤りは chrony 自身が `Fatal error` で止まる。起動したときの設定に `local` は書かない。見張りのループが 60 秒ごとに busybox の `adjtimex` でカーネルの `maxerror` を読み、しきい値(3.6 秒。timesyncd で最後の同期から 2 時間。定数)以下なら `chronyc local stratum 10`、超えたら `chronyc local off` を送り、状態が変わったときだけ `koitohan: serving ...` / `koitohan: stopped serving ...` をログに出す。止めているあいだは「同期していない」(stratum 0)と答える。カーネルの UNSYNC の印は約 9 時間後にしか立たないので使わない。しきい値を変えられるのはテストだけ(`NTP_MAX_ERROR_US`。`compose.yaml` には書かず、`tests/compose.test.yaml` が渡す。`.env.sample` にも載せない)。chronyd が終わるとコンテナも終わり、`docker stop` では chronyd の終了ステータスを返す。`container_name` だけは `${NTP_CONTAINER_NAME:-chrony}` と既定を持たせている。Compose は使わないサービスの値も検証するので、既定がないと、この変数のない `.env` ではすべてのコマンドが失敗する。ホストがすでに NTP サーバなら、このサービスは使わずにホストに配らせる(123/udp がぶつかる)。配っている最中に止まる流れ(`local off`)はテストしていない(ユーザーの判断。設計は `docs/basic-design.md` の 3.6 節)。
